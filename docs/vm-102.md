# VM 102 `claude-room` — como foi feita e como operar

Criada em 2026-11-13 no `pve01` (Proxmox 9.2). Detalhe completo no #2104, doc `14`, seção 9.

## Resumo
- Debian 12 genericcloud · 4 vCPU · 8 GB · 60 GB · `onboot`, `startup order=4`, fora do vzdump.
- Rede NAT `vmbr2` (`10.10.10.0/24`), VM `10.10.10.10`, gateway `10.10.10.1`. Só internet: bloqueia `192.168.0.0/16`, `172.16.0.0/12`, `10.0.0.0/8` e novas conexões VM→host.
- Docker 29.9.3 + Compose 5.7.1. Usuário `claude` (sudo sem senha), só chave.

## Acessar (do notebook do Caio)
```
ssh -o ProxyCommand="ssh -i ~/.ssh/id_ed25519_pve01 -W %h:%p root@192.168.100.251" -i ~/.ssh/id_ed25519_claude_room claude@10.10.10.10
```

## Subir / parar
```
cd ~/claude_room
docker compose up -d workspace                 # workspace
docker compose --profile oracle up -d oracle   # Oracle XE (precisa ORACLE_PASSWORD no .env)
docker compose down
```

## Oracle de teste
PDB `XEPDB1`, usuário `SYSTEM`, senha em `~/claude_room/.env` (não está no repo).
```
set -a; . ./.env; set +a
docker exec -i -e P="$ORACLE_PASSWORD" claude_room_oracle bash -c 'sqlplus -s system/$P@//localhost:1521/XEPDB1'
```

## Lições
- Imagem genericcloud não lê o drive cloud-init em IDE na `q35`: usar `scsi1`.
- `INPUT DROP` em `vmbr2` precisa de `ESTABLISHED,RELATED` antes.
- `docker compose` interpola variáveis de todos os serviços: `ORACLE_PASSWORD` com default vazio.
- Comandos longos por SSH: rodar em background (a sessão do Claude dá timeout em 120 s).

## Reverter
`qm stop 102; qm destroy 102 --purge` no `pve01`; remover o bloco `vmbr2` do `/etc/network/interfaces` (ou voltar `/root/interfaces.pre-vmbr2`) e `ifreload -a`.
